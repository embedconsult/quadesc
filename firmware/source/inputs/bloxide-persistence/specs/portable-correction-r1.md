# Portable R1 implementation clarification

R1–R9, M and Q remain normative and unchanged. This document specifies the concrete
owned API implementing them; it is not a wire protocol or a hardware qualification.

`BackendConfig` contains backend-qualified finite per-command/quiesce durations and
an authority-issued `WearLease`. `take_command(now)` binds an absolute deadline to
publication; `advance_time(now)` transitions a silent command to unresolved
Indeterminate and enables one owned `QuiesceRequest`. The pump must call time
advancement using the same monotonic domain. No timer is armed/rearmed implicitly
by polling. Saturating deadline addition is conservative at clock exhaustion.
`save` takes a synchronous clock callback and samples again after registered
validation immediately before acceptance/same-value decision.

`Failed { quiescent:false }` is diagnostic, not command retirement. The full
outstanding header and capture remain owned. `retained()` may expose Indeterminate
while `ownership_settled()` is false; this cannot be released. A late exact settled
completion or `complete_quiesce` with idle-and-drained proof permits bounded
reconciliation and may refine that notification. Once ownership is settled, the
terminal is immutable until Release. Quiesce failure/timeout does not establish
idle; it cannot restart quiesce or discard the original operation. A published
quiesce request must itself complete before release, even if the original command
completes late. An idle quiesce acknowledgement asserts the old completion slot was
also drained; late completions after that acknowledgement are rejected.

Marker uncertainty starts when its command leaves the service. Healthy complete
readback can prove exact Durable or definite absence; read/ECC/failure cannot.
The normal committed scan or reconciliation scan consumes the sole post-marker
scan allowance; failure cannot restart it. A write lock only permits that read-only
scan, never a new permit/erase/program. Quarantine survives Reset and late success.

`WearLease` is generated by the authority outside the MCU reset domain. It is not
an MCU epoch or a guessed globally unique boot ID. `WearGranted { permit }` names an
authority-issued receipt; `Erase { permit }` must consume it once before hardware
admission. The simulator keeps a fixed-capacity receipt table, durable lease counter,
remaining budgets and spent bits outside the replaced MCU service. A fresh lease
invalidates all older lease receipts without refund. Repeated acquire within one
lease replays the same receipt, including after it is spent; replay never funds
another erase. Loss of authority qualification denies new leases/erases. Actual
host-process persistence and physical wear authority remain T16 prerequisites.
