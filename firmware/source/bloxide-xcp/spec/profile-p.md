# Restricted profile P host adapter (T17-I6)

This is the reviewed D1/D2 application profile for a matched, dedicated UART LED client. It is additive to immutable S0. S0 `Session` still returns FE20 for all F9 packets. No generic XCP conformance, MCU image, flash qualification, or physical UART result follows from this host adapter.

## Boundaries and source pins

`xcp-profile-p` owns one P protocol session, PAG/F9/status, the 640-byte retained view and 128-byte identity block, four fixed read latches, and reconnect fences. It borrows the T07 `Owner` through `Domain<V>` and the actual `PersistenceService<S>` and `Broker<4>`. `Domain::write_scalar` must call the existing validated Owner apply path. The profile never stores or mutates a second LED state. The application supplies disarmed/maintenance/schema policy, the selected P identity and addresses, and backend/transport drain facts. The external async pump calls `take_command` and `complete_backend` with owned commands/completions outside HSM actions. Logical Reset calls `logical_reset` on the same retained instance; boot creates a new instance after R3 recovery and Owner initialization.

Exact reviewed source is persistence `5d67c9977c94ab74edde4821f5f880fe15ed65ac` (tree `da668f8949691982b4053654582113b192eb52cf`) and calibration `c0a693a8811d920d05850cfc2ebcfd7956a2741b`. The root Cargo manifest uses their reviewed local paths under this swarm layout; `tools/check_profile_p_inputs.py` verifies heads, clean tracked state and byte-identical copied metadata. T34 T08/T10/framework pins remain in `integration-lock.json`. No independent Git acquisition claim is made.

`ProfileP::new` checks identity layout and rejects absent/uniform synthetic hashes. The dedicated client additionally verifies the actual image, parsed A2L, descriptor and policy hashes before any E6/F9 or DOWNLOAD. The host fixture loads an acyclic identity at process startup from a separate file generated from the compiled host executable and exact fixture inputs. It is marked `host_fixture_only`; production admission refuses it. MCU composition must generate its own identity from the final image and metadata after final address allocation and bind it through the same checks.

## Save and readback

F9 is exactly `F9 01 00 00`; the sole page must have FREEZE explicitly selected. Known policy/schema/write-lock/deadline refusals precede reserve/capture/save. Accepted C is copied from `capture_owner` before the one FF, and backend progress is observed later through the real service. `observe` records an exact settled terminal in Broker before service/Broker release; unsettled Indeterminate keeps custody. A staged ambiguous result keeps its key and snapshot separately from the previous accepted summary and fences the wire until `reconcile_staged`. For internal clients 1–3, `retain_client_capture` stages one candidate in that same fixed scratch; the application calls service `save` and then `finish_client_save` in the same serialized turn. Only exact Accepted or fast Durable admission replaces the accepted summary. Exact rejected admission retires its service/Broker key and preserves the predecessor key, C and result. Failures leave the originating connection's request bit set, with no event or second F9 response. A diagnostic reconnect requires the application to supply all true idle/drain facts, remains read-only, and needs a new CONNECT. E6 and EB selection controls refuse with FE27 after their existing validation; E5 and readback remain available, while F9 and DOWNLOAD remain denied. Normal namespace advance performs checked exact +1 and both Broker/service handshakes; partial failure stays fenced.

The 640-byte view follows the approved offsets and distinguishes retained C, current durable record and live Owner RAM. The wire client latches at `SET_MTA(0x10000)`, seeks within the same latch and reads sequential 1..7-byte chunks. Other three clients have separate fixed latches and cursors. Errors leave cursor unchanged; exact-end retires a latch. The immutable identity is at `0x10400`. Fixture addresses must be replaced only by reviewed composition. No record/schema or portable R1–R9 API was changed.
