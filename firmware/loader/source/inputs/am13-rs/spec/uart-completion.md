# UART transmit completion and admission

`is_tx_complete(&mut self)` means all data admitted through this owner has left the transmitter, including the final stop bit. It returns true before the first successful write regardless of reception. Async `flush` uses this query, retrying via the existing 100 us timer. The former `is_tx_idle` API has been removed; downstream callers must use `is_tx_complete`.

Primary authority: TI SPRUJF2B, March 2026/revised August 2026, §29.2.2.5 and §29.5.2.6 (RIS at UART+0x30), §29.5.2.9 (ICLR at +0x48), and §29.5.2.21 (STAT at +0x108). RIS.EOT bit12 asserts only after the last data/flag bit, including STOP, leaves the serializer with no remaining TX buffer data. RIS supports polling regardless of IMASK; writing one to ICLR.EOT clears only that flag. SDK26.01.00.03 `hw_unicommuart.h` agrees. BUSY also covers reception. TXFE describes the buffer, not the serializer, so neither is used as TX completion. The owner keeps one boolean, `tx_pending`, initialized false after peripheral reset/configuration. A successful admission clears stale EOT while no transmission is outstanding, sets the boolean, then writes TXDATA. A pending byte becomes complete only on observed raw EOT. Polling records that completion in the owner without clearing the peripheral flag. The next successful admission clears that old flag before TXDATA. No EOT interrupt is enabled or needed; reset leaves masks disabled. No IIDX read or shared interrupt/DMA owner may consume these indications.

Admission deliberately waits for the previous byte's EOT even if TXFF is clear. At most one byte is outstanding; this forgoes FIFO/serializer pipelining. Allowing another byte while the previous one was shifting would permit an old EOT between clear and TXDATA, falsely completing the new byte. Clearing after TXDATA would instead risk losing a new completion during preemption. Serial admission avoids both races without an interrupt-disabled timing window, guessed transmission delay, or undocumented automatic flag clearing.

Cases and interleavings:

- Before any write, RX-only BUSY and RX errors do not create TX work. Stale EOT is immaterial until cleared before the first admission.
- TXFF rejection happens first and performs no write or state transition. A pending-byte rejection leaves EOT untouched. Under exclusive ownership the buffer cannot become newly full between TXFF read and TXDATA; only this foreground owner can add data.
- If old TX completes before the RIS read, admission can proceed after clearing its EOT. If it completes after a read returning zero, that call returns would-block and a later call observes completion. No byte is silently admitted by a failed call.
- Once old completion is observed, no old TX can finish during the clear-to-write interval. Arbitrarily long preemption before TXDATA is safe. Preemption after TXDATA can let new TX finish immediately; there is no subsequent clear to lose that EOT.
- Repeated completion queries/flush calls remain complete until the next successful admission. Consecutive batches cannot consume a stale flag as their completion.
- Dropping a pending async write admits no byte. Successful writes return one admitted byte immediately without an await after admission. `write_all` may have sent a prefix when cancelled, so the protocol owner must track progress. Dropping/recreating or repolling flush preserves the boolean and raw EOT; it never aborts an admitted transmission.
- RX error clearing masks exclude EOT. EOT clearing masks exclude RX/error flags. Concurrent hardware reception or error indications cannot complete TX and are left for `try_read`. Flush itself does not consume or report RX errors. The exclusive mutable handle still requires the transport service to schedule/drain RX between TX operations; full-duplex throughput/overrun qualification is not implied.

Bounds: `try_write` performs at most two MMIO reads and two MMIO writes, with no loop or critical section. `is_tx_complete` performs at most one read, zero writes; an already complete owner performs none. Fixed RAM cost is one boolean (struct padding/layout may differ); no allocation, dynamic queue, IRQ, or new timer slot beyond existing async waits. Async waits have no inherent wall-clock timeout: stuck hardware stays pending, and owners can apply `with_timeout`. Cancelling a timeout does not authorize peripheral reacquisition/reset. Polling adds the configured timer quantum plus executor/interrupt latency after hardware EOT; the actual bound requires HIL. At one byte per admission, UART saturation and loaded edge/poll latency must be requalified; no line-rate guarantee is made.

Tests use a fixed-storage peripheral model with separate holding/data/stop phases, W1C flags, reception and injected completions at MMIO boundaries. The real Embassy workload covers empty/admitted/cancelled/repoll/repeated-batch paths, RX errors and all-four allocator counters. These are host semantics tests, not native ARM64 execution, measured UART timing or full-image T36 acceptance. The qualified physical diagnostic baseline stays 19200; 38400 remains an unqualified candidate.
