# T06 / T13 integration handoff

Consume am13-rs and esc-som-board as platform implementation libraries. No HAL type belongs in a message, portable context or blox. The mailbox-free LED output service receives the moved `Led` GPIO plus its feature-owned output-slot consumer. The owner keeps the portable producer; T05 does not reinterpret Applied/Ready/epoch/quiesce/revision/retirement semantics.

1. Select Rust1.94.0, thumbv8m.main-none-eabi soft float; cortex-m-rt0.7.6 (`set-sp`, `set-vtor`, `zero-init-ram`). Firmware owns `memory.x`: initial RAM 0x20000000+96KiB, FLASH 0+512KiB. No persistence/update partition is implied.
2. Use exactly one `Peripherals::take`, then `esc_som_board::initialize`. Acquire before actor/service Start. A failed acquire/init does not return reusable hardware; halt safely. Physical outputs after any failure still require electrical evidence. The safe API never arms a motor.
3. Resources are owned values, not borrowed globals. Move LED and UART into sole thread executor services. Preserve them across actor Reset/Stop; never reacquire. GPIO setup is consumed, so services cannot remux any other pads. UART no_std async adapter waits in the service, never in synchronous RTC actions.
4. Construct all storage/tasks/endpoints and freeze all allocator operations. Consume `systick.start(clocks)` and enable CPU interrupts only at this barrier, before the first service/actor polls and external admission. `embassy` exports exactly one SysTick handler. No competing generic time driver or second tick handler. No generic Embassy timer queue features needed.
5. Pin embassy-executor=0.9.1, embassy-time=0.5.1, embassy-time-driver=0.2.2 (`tick-hz-10_000`), critical-section=1.2.0. Target picks cortex-m=0.7.7 `critical-section-single-core`, and executor `arch-cortex-m,executor-thread`; host test supplies critical-section/std only. Do not enable embassy-time/std/mock-driver or a second critical-section implementation in target dependencies. Locks record transitive checksums.
6. Budget at most 16 retained task deadlines, including cancelled/completed tasks whose earlier timer registration has not yet expired. Tasks are statically allocated process-lifetime resources. The table deduplicates by task and keeps earliest deadline; Timer repolls/re-registers if that wake was early. No task reclamation or queue growth. Exhaustion is a fatal bounded fault; do not treat it as a recoverable calibration reject. Non-Embassy wakers are rejected by upstream task_from_waker validation.
7. Read `Instant::now().as_ticks()` in 100us units; `timer::ticks_to_micros` is checked, `micros_to_ticks_ceil` never rounds a deadline earlier. u64 state uses critical sections, not AtomicU64. Time cannot go backward; boot starts at zero and actor reset never resets it.
8. SysTick loses wraps when masked/delayed for >=100us; this driver does not pretend to recover them. Measure total interrupt masking and wake/edge lateness under traffic. No STOP/STANDBY or dynamic clock changes. Timer quantization and executor scheduling add latency; 100us is configured quantum, not measured worst-case latency. LED idle polling contract stays <=1000us; choose earlier physical edge deadlines.
9. UART has no DMA/peripheral IRQ and no application queues here. Async read/write return one byte per success, and flush waits for the admitted byte’s raw EOT through its final stop bit, independent of RX. `is_tx_complete` is the synchronous query. Only one byte may be outstanding; callers must handle would-block even when the TX buffer has space. See [TX completion](uart-completion.md) for bounds and throughput implications. Cancelling/recreating flush preserves completion state in the UART owner and does not cancel transmission. Calls can be bounded with `with_timeout`; dropping a pending read/write has not admitted a byte. `write_all` cancelled after prior successful writes may have transmitted a prefix: owned protocol command/completion service must retain its progress or report truncation. This is normal I/O behavior, not an exactly-once command promise. Error is passed to transport owner for framing/session recovery. 38400 remains a qualification candidate.
10. Full firmware implements allocation-free panic/HardFault/default exception policy; no Drop cleanup is assumed on fault. Sample uses a no-allocation interrupt-disabled halt. BSL reset(false) recovery and clock/UART/LED/timebase measurements belong to the serialized Jetson custodian after artifact review.

No contract ambiguity discovered requiring S0 edits. Remaining constraints are implementation integration and HIL proof obligations, not changes to accepted contracts. Parent/coordinator owns acceptance and dispatch.
